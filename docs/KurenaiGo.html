KurenaiGo ドキュメント

KurenaiGoは、KurenaiEngine (KurenaiEngine2D)で描画し、KataGo をGTP経由の対局相手として使う囲碁(Go)アプリです。このドキュメントでは、アプリ本体 (KurenaiGo/Source/以下)の実装内容を説明します。KurenaiEngine自体のAPIリファレンスは KurenaiEngine/docs/KurenaiEngine.html を参照してください。

1. 現在の実装範囲KataGoとの対局が可能

19路盤の表示、マウスでの着手、合法手判定・捕獲・シンプルコウを含むルール、そして KataGoをGTP(Go Text Protocol)経由の 子プロセスとして起動しての対局(人間=黒、KataGo=白)までを実装しています。色の選択・ ハンディキャップ・対局のリスタートは未実装です(8章参照)。

2. 座標系とレイアウト

KurenaiEngine2Dのワールド座標はウィンドウのピクセル座標そのもので、原点は画面左下、 Y-upです(DrawSpriteのx, yはスプライト中心)。KurenaiGoではウィンドウの リサイズに追従できるよう、毎フレーム renderer.GetWidth()/GetHeight() から 盤のレイアウトを再計算しています(ComputeBoardLayout)。 

struct BoardLayout
{
    float CenterX;      // 盤の中心(ウィンドウ中心)
    float CenterY;
    float BoardExtent;  // 木目の盤面の一辺の長さ
    float GridExtent;   // 格子線が占める範囲の一辺の長さ(盤面より内側)
    float LineSpacing;  // 目の間隔 = GridExtent / (kBoardLines - 1)
};
  • BoardExtentはウィンドウの短辺 × kBoardExtentRatio(0.88)。 常に正方形になるよう短辺基準で計算する。
  • GridExtentはBoardExtent × kGridExtentRatio(0.90)。 盤面の外周に木目の縁が見えるよう、格子線の範囲を一回り小さくしている。
  • 格子線のインデックス(0〜18)からワールド座標への変換は GridIndexToCoordinateが行う(中心からGridExtentの半分だけ引いた位置を 起点に、LineSpacing刻みで並べる)。

3. 盤・石の描画

KurenaiEngine2D::DrawSpriteは矩形(回転可能)のスプライトしか描画できないため、 盤面・格子線・星は矩形スプライトの組み合わせで表現しています(円形のテクスチャは使っていません)。

要素描画方法
盤面(木目)1x1の白テクスチャを木目色でティントした正方形スプライト1枚
格子線(縦横19本ずつ、計38本)細長い矩形スプライト。横線は幅=GridExtent・高さ=線の太さ、縦線はその逆
星(hoshi、3x3=9箇所)格子の交点(0-indexedで3, 9, 15)に小さな正方形スプライトを配置(円ではなく点の代用)
石(黒・白)Assets/stone_black.png / stone_white.png(アルファ付きPNG)を LoadTextureで読み込み、GoBoardの石がある交点に配置

盤面・格子線・星はCreateSolidColorTexture(255, 255, 255, 255)で作成した白1色の テクスチャを1つだけ使い回し、DrawSpriteのr, g, b, a引数(乗算ティント)で 色を出し分けています(Samples/Sample2Dと同じ手法)。石だけは矩形スプライトでは 円に見せられないため、Tools/generate_stone_textures.ps1(GDI+のアンチエイリアス付き 楕円描画)で事前生成したPNGを実テクスチャとして読み込んでいます。人間の手番中、カーソルに 最も近い空点交点には半透明の白石テクスチャ(タイントで薄いグレー・半透明化)をプレビュー表示します。

4. ルールエンジン(GoBoard)

KurenaiGo::GoBoard(Source/GoBoard.h/.cpp)は盤面と囲碁のルールのみを 扱う、描画・入力から独立したクラスです。座標はrow=0が盤の下端・col=0が 左端(row*Size+colの1次元配列)で、これは2章のワールド座標系(インデックス0が下/左) およびGTPの座標系(行1=下端、列A=左端)の両方と一致するため、変換が単純になります。

4.1 合法手判定と捕獲

TryPlay(row, col, color)は次の順序で処理します。

  1. 空点でなければ非合法。シンプルコウで禁止されている地点なら非合法。
  2. 石を仮に置き、隣接する相手グループをフラッドフィル(CollectGroup)で走査して 呼吸点(liberty)を数える。呼吸点0のグループがあれば取り上げる(複数方向から同じグループに 到達する場合の重複除去あり)。
  3. 相手を取り上げた後、自分のグループの呼吸点を再計算する。0なら自殺手として非合法・ 全ての変更をロールバックする。
  4. 合法なら確定し、連続パス数を0にリセットする。

4.2 シンプルコウ

直前の手が「相手をちょうど1つ取り、打った石自身が呼吸点1つ(その取った地点)だけの単独石になる」 形だった場合、その地点への即座の再着手を次の1手だけ禁止します(m_KoForbiddenIndex)。 パスを含むいずれかの着手が行われるとこの制約は解除されます。より厳密な超劫(局面の反復)判定は 行っておらず、一般的なアプリで広く使われる簡易版のコウ規則です。

4.3 地の計算をしない理由

GoBoard自体は地の計算(スコアリング)を行いません。生きた石・死んだ石の判定 (セキ等の特殊な形を含む)を自前実装するのは複雑で誤りやすいため、対局終了(両者パス)時は KataGoのfinal_score(7章)にスコアリングを委譲しています。

5. マウス入力

docs/KurenaiEngine.html 5章の通り、KurenaiEngine2D自体は入力を提供せず Win32 APIを直接使う設計です。ただしKurenaiEngineBaseはHWNDを公開していないため、 ScreenToClientで座標変換するための自ウィンドウHWNDが取得できません。KurenaiGoでは 起動直後に一度だけFindWindowW(L"KurenaiEngineWindowClass", L"KurenaiGo")で自ウィンドウを 検索して補っています(KurenaiEngineWindowClassはエンジン内部で登録している固定の ウィンドウクラス名。Core/Window.cpp参照)。

毎フレームGetCursorPos→ScreenToClientでクライアント座標(原点は左上、 Y-down)を取得し、height - clientYでワールド座標(原点は左下、Y-up)に変換します。 最も近い交点との距離がLineSpacingの40%以内であればその交点を「ホバー中」とみなします (TryGetHoveredIntersection)。クリック・パス・投了はいずれも GetAsyncKeyStateの状態を前フレームと比較した立ち上がりエッジで検出しており、 キー/ボタンを押し続けても1回しか発火しません。

6. 対局の進行(状態遷移)

Main.cppのTurnStateで対局の進行を管理します。

状態内容
EngineStartingKataGo起動中。KataGoClient::IsStartupComplete()をポーリング
HumanToMove黒(人間)の手番。クリック/P/Rを受け付ける
AIThinking白(KataGo)のgenmove応答待ち。TryGetGenMoveResultをポーリング
WaitingForScore両者パス後、final_score応答待ち
GameOver対局終了。入力を受け付けず盤面のみ表示し続ける

対局終了・投了・通信エラーはKurenaiEngine2Dに文字描画機能が無いため、既存の エラーダイアログ(MessageBoxA)と同じ手法で通知します。

7. KataGo連携(KataGoClient)

KurenaiGo::KataGoClient(Source/KataGoClient.h/.cpp)は katago.exeをgtp -model <model.bin.gz> -config <gtp.cfg>で 子プロセス起動し、標準入出力を匿名パイプでリダイレクトしてGTPのテキストコマンド/応答を やり取りします(CreateProcessW + CreatePipeによるWin32の標準的な 「リダイレクトされた入出力を持つ子プロセス」の実装)。標準エラー出力(チューニング進捗等の 診断ログ)はKataGo/katago_stderr.logへリダイレクトしています。

7.1 非同期処理

起動処理(StartAsync)とKataGoの着手要求(RequestGenMove)・終局判定 (RequestFinalScore)は、OpenCLの初回チューニング(数十秒)やKataGoの思考時間 (time_settings 0 5 1で最大5秒/手)がかかるため、いずれも専用スレッドで実行します。 メインの描画ループはTryGetGenMoveResult等のポーリングで結果を受け取るだけなので、 KataGoが応答を返すまでの間もウィンドウは応答なしにならず、盤面の再描画・リサイズ処理を続けられます。

7.2 座標変換

GTPの座標は列がA〜T(Iを除く)、行が盤の下端から1始まりの数字です。 GoBoardの座標系(row=0が下端、col=0が左端)と対応しているため、 ToVertex/ParseVertexでの変換は「列インデックスに応じてAから 数え上げ、Iをまたぐ場合は1つ増やす」「行はインデックス+1」という単純な計算のみで 行っています。

7.3 GTPコマンド

コマンド用途
boardsize 19 / clear_board / komi 7.5 / time_settings 0 5 1起動直後のハンドシェイク(StartAsync)
play <B|W> <vertex|pass>人間の着手・パスをKataGo側の盤面にも反映する
genmove <B|W>KataGoに着手を生成させる。応答は着手・pass・resignのいずれか
final_score両者パス後の結果(例: B+3.5)取得
quit終了時にデストラクタから送信

7.4 終了処理

KataGoClientのデストラクタは、進行中のワーカースレッドの完了を待ってから quitを送信し、プロセス終了を最大3秒待って、それでも終了しない場合は TerminateProcessで強制終了します。これによりKurenaiGoを閉じてもkatago.exeが 残留しません。
